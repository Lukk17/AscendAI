Tasks are ordered so that everything which shapes stored data lands before anything that reads it: context plumbing, then the Postgres schema, then the write path that stamps payloads and keys, then the Qdrant payload indexes, and only then the retrieval filter and the presign guard that depend on those payloads existing. Tenant isolation starts from empty stores (owner answer 88.1 of 2026-10-08, which supersedes answer 72.2 of 2026-10-06): the owner starts from clean stores after these changes are built, so no data written before this change needs to survive, and no task converts, moves or backfills Redis keys, Qdrant points, objects or AscendMemory entries. The Flyway migration of section 2 still adds the `chat_history.tenant_id` column with its foreign key. The data that exists today in the development stores is disposable and out of scope (owner answer 73.1 of 2026-10-06): no task converts it or depends on it, and every test seeds its own data. Every task states the observable check that proves it is done. None of them is satisfied by a log line.
