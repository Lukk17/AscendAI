## 4. Suspension enforcement

- [ ] 4.1 Add a request filter of this change, placed after the authentication of `add-keycloak-login`, that reads `TenantContext.currentTenantId()` and answers 403 when the tenant's `status` is `SUSPENDED` (fail-closed), covering every data-plane operation at one point. It reads the status through a Caffeine cache with a bounded time to live `app.tenant.status-cache.ttl` of 30 seconds and a bounded size `app.tenant.status-cache.max-size` of 1000 entries (owner answers 87 and 98.4 of 2026-10-08, design D4), settings under owner rule 98: `application.yaml` writes `ttl: ${APP_TENANT_STATUSCACHE_TTL:30s}` and `max-size: ${APP_TENANT_STATUSCACHE_MAXSIZE:1000}`, the properties record carries the same defaults, and the `ascend-agent` compose service writes `- APP_TENANT_STATUSCACHE_TTL=${APP_TENANT_STATUSCACHE_TTL:-30s}` and `- APP_TENANT_STATUSCACHE_MAXSIZE=${APP_TENANT_STATUSCACHE_MAXSIZE:-1000}`. Suspend and resume call `pg_notify('tenant_status_changed', <tenantId>)` in the transaction that changes the row, and a `PostgresNotificationHandler` for that channel, registered on the one `PostgresNotificationListener` of `add-keycloak-login` D20 (no `LISTEN` connection of this change's own), evicts that tenant's entry on every agent instance and clears the whole status cache in its `onReconnect()`. No class of an earlier change is edited. Acceptance: task 4.3 passes, an integration test with two application contexts against one Testcontainers Postgres shows a suspend made through the first is refused on the second at its next request, well before the time to live, and a binding test reads 30 seconds and 1000 with neither variable set and the values of the two variables when they are set

Acceptance: in the Keycloak Testcontainer test a user of the tenant is disabled through task 5.1, the tenant is suspended, another user of it obtains a token and gets 403 on chat, the tenant is resumed, the disabled user still cannot obtain a token, the other user is authorized again, and neither suspend nor resume sends a request to the Keycloak Admin API
