## Why

The four Python services (ascend-audio-scribe, ascend-web-hunter, ascend-memory, ascend-ocr) each carry their own copy of the same cross-cutting code: error handlers, the settings class, logging setup, request id middleware, OpenTelemetry setup, readiness checks and the app wiring in `main.py`. A read-only measurement found about 1,000 duplicated lines, and the copies have drifted apart: three services ignore their `LOG_LEVEL` setting, only ascend-ocr has rate limiting, ascend-ocr does not answer RFC 7807 problem bodies while the other three do, ascend-web-hunter pins older OpenTelemetry versions, ascend-memory names its MCP server `AscendMemory`, and ascend-audio-scribe names its port setting `MCP_PORT`. The owner decided on 2026-10-03 (answer 56) to create one shared Python library, `ascend-python-common`, that all four services import, so they align in configuration, error handling, logging and behaviour. It must exist before the later Python changes, because three of them already plan their own error helper.

## What Changes

- New library `ascend-python-common` under `libs/ascend-python-common/`, a normal Python dependency declared in each service's `pyproject.toml`, with its own test suite under the 100 percent branch coverage gate, its own version and changelog. It is installed from its folder in this repository: editable in local virtual environments, and in Docker through a Compose additional build context. It is not published to any package index (owner answer of 2026-10-03).
- Library modules: errors (one problem body builder, a code registry, handler registration for service exceptions and for the framework's own errors, refusal logging, one error counter per code, surface and operation, the MCP tool error mapping), a settings base class, logging (JSON or color by `LOG_FORMAT`, honouring `LOG_LEVEL`, MCP session token masking), request id and MCP session digest middleware (pure ASGI), tracing, readiness aggregation, rate limiting on REST and MCP, the startup banner frame and its printing rules (layout, alignment, check status lines, secret masking, while each service passes its own content lines), the URI fetch guard (the SSRF check and the `file://` jail of ascend-ocr and ascend-audio-scribe, and the public address rule, address pinning and redirect checks of ascend-web-hunter's `src/validator/url_validator.py`, so the rule exists once, owner answers 60.5 of 2026-10-03 and 63.2 of 2026-10-04), the app factory that wires FastAPI, the FastMCP lifespan, `/health`, `/ready` and `/metrics`, and a shared tooling configuration (ruff, mypy strict, pytest with strict markers and the coverage gate) that each service extends.
- Each service keeps only its business code, its own error codes, its own settings fields and its own readiness probes. The four services migrate one at a time, each green before the next.
- Every REST error of every Python service becomes an `application/problem+json` body with `type`, `title`, `status`, `detail`, `instance`, `code` and `traceId`. This change defines that shape itself (owner answer 70.1 of 2026-10-04), and `upgrade-spring-boot-4` D19 later gives the agent the same shape. There is no exception (owner answer 60.2 of 2026-10-03): ascend-web-hunter's 428 (human help needed) and 409 (remote browser busy) answers are problem bodies too. Only the internal 500 gets a fixed generic detail. An error that reports another service or an upstream (502, 503, 504, and the upstream codes a service names, such as ascend-ocr's `DOWNLOAD_FAILED`) keeps its useful detail. A refused service token answers 401 with the platform code `unauthorized`, the code `add-keycloak-login` uses. A request validation failure answers 400 with code `validation` and an `errors` list. An unknown path answers a problem 404 and a wrong method a problem 405, which ascend-ocr does not do today (measured: a plain text `Not Found` from the MCP mount).
- BREAKING: ascend-ocr moves from its `{"code", "detail"}` body to the problem body and keeps its codes (`QUEUE_FULL`, `JOB_NOT_FOUND` and the rest) in the `code` field. The ascend-agent Pact consumer test and the committed pact are updated in the same step. `AscendOcrClient` already reads only the `code` field and needs no code change.
- BREAKING: request validation failures move from FastAPI's 422 to 400 with code `validation` in all four services, the rule `upgrade-spring-boot-4` D19 point 5 later sets for the agent too.
- BREAKING: the setting `MCP_ALLOWED_HOSTS` is renamed to `ALLOWED_PRIVATE_HOSTS` in the library and in all four Python services (owner answer 68.2 of 2026-10-04). It names the hosts the URI fetch guard may reach even at a private address, and the new name says that without tying it to MCP, because ascend-web-hunter uses it on REST too. Today only ascend-ocr and ascend-audio-scribe read it, ascend-web-hunter gets it in this change under the new name, and ascend-memory fetches no caller URI and reads neither name. Every file that sets or documents the old name today is moved to the new one, among them the two `compose.yaml` lines of `ascend-ocr` and `ascend-audio-scribe`. A service built on the library refuses to start while `MCP_ALLOWED_HOSTS` is set in its environment, with a message that names `ALLOWED_PRIVATE_HOSTS` (owner answer 72.3 of 2026-10-06), so a leftover line in an old `.env` is never silently ignored. `harden-cloud-deployment` lands later and uses only the new name. `MCP_ALLOWED_HOST_HEADERS` of `add-python-runtime-upgrades` is a different setting and keeps its name. Every later change uses `ALLOWED_PRIVATE_HOSTS`.
- BREAKING: `/ready` answers 200 when ready and 503 when not ready in all four services, with one body shape. ascend-ocr answered 200 in both states until now.
- BREAKING (ascend-web-hunter): the REST 428 and 409 answers move from their `status`-keyed bodies to problem bodies. The old `status` word moves to `code` (`human_intervention_required`, `novnc_busy`), `message` becomes `detail`, `status` becomes the HTTP status number, and `intervention_type`, `vnc_url`, `holder_url` and `holder_profile` stay as extension members with the same names and meaning. The 409 keeps its `Retry-After` header. This supersedes the body shape of ascend-web-hunter's ADR-003, which is amended at implementation time. No ascend-agent code reads either REST body (see `design.md` D5).
- BREAKING: MCP refusals in all four services are tool errors whose text starts with the code. ascend-audio-scribe and ascend-memory returned a `{"status": "error", "code": ...}` result object until now. The MCP status objects of ascend-web-hunter (`human_intervention_required`, `novnc_busy`, `session_expired`) are successful tool results, not errors, and stay as they are.
- Defects fixed, one task each: logging honours `LOG_LEVEL` in all four. Rate limiting in all four, with per-service limits in settings, also on MCP tool calls (ascend-ocr's own AGENTS.md says `ocr_submit` is limited, the code does not limit it). The limits are flood protection, not a throughput cap (owner answer 60.4 of 2026-10-03): `RATE_LIMIT_DEFAULT` is `1200/minute` in ascend-web-hunter, `6000/minute` in ascend-memory, `600/minute` in ascend-audio-scribe and ascend-ocr, with `RATE_LIMIT_TRANSCRIBE=60/minute` and `RATE_LIMIT_OCR=60/minute` on the transcription and submission operations. ascend-ocr's old `60/minute` and `20/minute` were the only real settings, and none of the values was measured. They stay the defaults, because owner decision 91.3 of 2026-10-08 removed the load test that was to set final values. Several containers of one service share one caller budget through Redis where the service has one (ascend-web-hunter), owner decision 87 of 2026-10-08. One OpenTelemetry version set for all four (ascend-web-hunter is on 1.42.1 and 0.63b1). ascend-memory's FastMCP server is named `ascend-memory`. ascend-ocr moves to RFC 7807. ascend-audio-scribe's port setting becomes `API_PORT`, so the `API_PORT=7017` its Dockerfile already sets takes effect.
- The MCP endpoint stays at `/mcp` on the API port in all four services (owner answer 58 of 2026-10-03). One port setting, `API_PORT`, exists everywhere, defined once in the library's `ServiceSettings` base. No service has an `MCP_PORT`. The MCP app is attached to that one path only, so every other path reaches the problem 404 and 405 answers.
- Every redirect target is checked again (owner answer 63.1 of 2026-10-04). The library's URI fetch guard follows redirects by hand, runs the public address check on each hop and stops after 10 hops. ascend-audio-scribe, which today lets aiohttp follow redirects after the first check only, uses it, so a public URL that redirects to a private address is refused. ascend-ocr still follows no redirect. ascend-web-hunter's curl_cffi tier keeps the same hop checks and pinning, now from the library.
- BREAKING (ascend-web-hunter): a URL with user info (`https://user:pass@host/`) is refused, as ascend-ocr already refuses it, and the refusal carries the code `unsafe_uri` (400) on REST and MCP.
- The security response headers ascend-ocr sends move into the library and all four services send them (owner answer 60.3 of 2026-10-03).
- BREAKING (ascend-web-hunter): the service now limits the request rate of each caller, which its main spec `web-search-antibot-evasion` forbids today. The requirement is modified so it forbids only outbound self-throttling per target domain.

## Capabilities

### New Capabilities

- `python-service-platform`: the behaviour every Python service shares through the library: the problem body for every REST error, refusal logging and counting, MCP tool errors, the settings every service reads, logging, the request id and MCP session digest, tracing with a trace id on every request, the `/health`, `/ready` and `/metrics` endpoints, rate limiting on both surfaces, the MCP endpoint path, the MCP server name, and the quality gates every service build passes.

### Modified Capabilities

- `ocr-page-resolution`: the scenario "A Korean submission over REST" asserts the old `{"code", "detail"}` body. It now asserts the problem body with the same code and detail.
- `ocr-service-readiness`: the requirement "Readiness reports whether the service can take work" keeps 200 in both states and the old body in a scenario named "Response shape and status are unchanged". OpenSpec does not let a MODIFIED block drop or rename a scenario, so the requirement is removed and added again as "Readiness answers 503 whenever the service cannot take work", with the same conditions and the shared readiness body that still separates busy from stuck.
- `ascend-agent-containerization`: the requirement "A `.env.example` documents the secrets compose consumes" gains the rule that the old name `MCP_ALLOWED_HOSTS` appears in no compose file and not in `.env.example`. `production-deployment` does not exist yet when this change lands. `harden-cloud-deployment` (build group 3, position 4) creates it later with `ALLOWED_PRIVATE_HOSTS` already in it (owner answer 72.1 of 2026-10-06).
- `service-metrics` (added by `add-observability`, build group 1): the requirement "Domain custom metrics - Python services" gains the ascend-audio-scribe, ascend-memory and ascend-web-hunter search rows that moved here from `add-observability` (design D24).
- `web-search-antibot-evasion`: the requirement "No service-side request rate limiting" forbids any per-caller limit. It is removed and added again as "No outbound self-throttling, and inbound limits only per caller", so the inbound per-caller limit of `python-service-platform` applies.
