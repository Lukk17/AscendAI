# Decision records for `add-document-connectors`

The monorepo records ADR-M004 through ADR-M009 under `docs/architecture/decisions/` settle permission-aware retrieval as a whole: mirroring access lists onto chunks, filtering inside the vector search, deny-by-default on a missing list, group principals with membership resolved at login, the email join across providers, and enforcement living in the agent.

The records here decide what this change decides on top of that. The `sync-freshness-check-replaces-the-sweep` record moved to `add-connector-framework` on 2026-10-04, with the freshness check it decides, when the framework was split out of this change (owner rule of 2026-10-04: the personal assistant comes first). They follow the format used by `apps/ascend-agent/docs/architecture/decisions/`. They carry no number yet. Each file is named `ADR-NNN-<slug>.md` and the drafts refer to each other by slug. Each one takes the next free number in that directory's sequence at implementation time, because ADR-010 is already taken there and numbers written now would collide.

Five of them were written for a scope that captured per-document access lists from the source. That capture is deferred, because group membership lives in Keycloak alone and no principal this version can mint equals an identifier a file store hands back, so a captured list would match nobody. Those records are marked deferred rather than deleted, with a dated deferral section stating what has to happen for each to become active. Their analysis is intact and returns with the work.

| :--- | :--- | :--- |
| [effective-permissions-not-change-feed](ADR-NNN-effective-permissions-not-change-feed.md) | Deferred | Capture reads effective permissions from the source rather than inferring them from the content change feed |
| [container-first-permission-capture](ADR-NNN-container-first-permission-capture.md) | Deferred | Permissions are captured container-first, with per-item reads only where a list is unique or due |

| [access-list-staleness-sweep](ADR-NNN-access-list-staleness-sweep.md) | Deferred, superseded for this scope by the `sync-freshness-check-replaces-the-sweep` record, which moved to `add-connector-framework` on 2026-10-04 | Access lists past a maximum age are emptied, converting a silent capture outage into visible degradation |
| [sharepoint-first-despite-google-being-cheaper](ADR-NNN-sharepoint-first-despite-google-being-cheaper.md) | Proposed, amended, corrected 2026-10-04 | SharePoint stays the first connector. The premise that Google Drive is cheaper to make permission-correct is corrected: files in shared drives need one `permissions.list` call per file |

On archive, only the records that are not deferred move to `apps/ascend-agent/docs/architecture/decisions/` unchanged, each taking the next free number in that sequence at implementation time: today that is `sharepoint-first-despite-google-being-cheaper`. The same step replaces `NNN` in its file name and title. A record's status moves from Proposed to Accepted when the change is approved for implementation. The five records marked Deferred are not installed: they stay in this folder of the archived change, with this index, where their analysis stays in git and returns with the capture work (owner answer 93, review item C1). The installed record's index entry in `apps/ascend-agent/docs/architecture/decisions/` names this archived folder as the place of the deferred records.
