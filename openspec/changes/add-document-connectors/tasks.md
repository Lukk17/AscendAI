## 0. Blocking dependencies

Build group 5, position 7 of the owner build order of 2026-10-04. The framework moved to `add-connector-framework` on 2026-10-04, and this change adds the `SHAREPOINT` type to it. Every change in the table lands before this one, so no task waits on a later change. Each task that uses an artifact of an earlier change carries a `blocked by:` marker naming the change and the artifact, as a reminder of what it builds on.

| Sibling change | What this change needs from it | Tasks blocked |
| :--- | :--- | :--- |
| `add-connector-framework` | `DocumentConnector`, the orchestrator and its landing contract, scheduling, run history, the freshness check, the `/api/v1/connectors` API with its `ADMIN` row, `ConnectorCredentialStore`, the named type check constraint and `docs/CONNECTORS.md` | every task |
| `add-tenant-isolation` | the tenant prefix implementation of `TenantPrefixResolver`, the tenant metadata carried into chunks, the four access-list metadata keys, the `tenant:everyone:{tenantId}` pseudo-group, and the ingestion producer default that stamps it onto a document with no source-captured list | 3.1, 5.1 |
| `add-auth-and-identity` | the test tenants and their users for the specs of section 5 | 5.1 |
| `upgrade-spring-boot-4` | Flyway as the agent's migration tool | 1.1 |

Nothing here is blocked on a directory identifier, a directory-namespaced principal, or a cross-provider identity link. This version captures no permissions from a source, so it consumes none of those. What that costs a customer is stated in the design's Named limitation section.

## 2. SharePoint and OneDrive connector

- [ ] 2.1 Implement the Graph auth client: client-credentials token acquisition per tenant with in-memory expiry-based caching, with the tenant id, client id and client secret resolved through `ConnectorCredentialStore` of `add-connector-framework` at sync time, never persisted outside it or logged. `SHAREPOINT` declares that it needs a credential.
  verify: test with a mocked token endpoint asserts one token acquisition serves multiple calls within its lifetime, a new one is acquired after expiry, a create without a credential is refused by the framework with `validation`, and neither the secret nor the token appears in captured logs or in the database outside the encrypted credential row.
- [ ] 2.2 Implement the Graph API client: site to drives resolution, drive delta requests (initial full enumeration and token-based incremental), delta-page pagination, item content download, and deserialization of the `deleted` facet.
  verify: a test against a local JDK `HttpServer` fake of Graph (as in `close-agent-test-gaps` D1) asserts a multi-page delta is fully consumed and a `deleted` facet entry is surfaced as a deletion.
- [ ] 2.3 Implement `SharePointConnector` content behaviour: folder-path scoping applied to delta results, MIME and size filters applied from Graph item metadata before download (skip with reason, no full download), delta entries mapped to `ChangeSet` add, update and delete entries carrying `source_type` `connector:sharepoint` and the Graph item's `webUrl` as `origin_uri` (`add-connector-framework` D21), one delta token persisted per drive in the framework's cursor table.
  verify: a test against the local Graph fake asserts an add, a modify, and a delete in one delta page produce an object storage write, an object storage overwrite, and a deletion-path invocation with correct run counters, an out-of-scope file produces no download and no outcome record, and a 2 GB item produces `SKIPPED` with a size reason and zero content bytes fetched.
- [ ] 2.4 Implement throttling compliance with one per-run budget: honour `Retry-After` on 429 and 503, exponential backoff with jitter otherwise, bounded per-request retries, and a per-run budget that when exhausted ends the run `PARTIAL` with the cursor advanced only through what was fully processed.
  verify: test asserts a 429 carrying `Retry-After: 7` is waited out for at least seven seconds and then retried successfully, and asserts budget exhaustion ends the run `PARTIAL` with a resumable content cursor.
- [ ] 2.5 Implement delta-token invalidation handling: on Graph 410 or a resync instruction, discard the token and re-enumerate the drive in full.
  verify: a test against the local Graph fake asserts the token is discarded and a tokenless delta is issued, a file whose bytes are unchanged keeps its point identifiers and is not re-embedded, and the run's `updated` counter is zero for those files.
- [ ] 2.6 Assert the connector requests and uses content permissions only: no directory, group, or group-member application permission in the setup path, and no request issued against a directory group endpoint.
  verify: a test against the local Graph fake asserts a full sync completes against a Graph fake that rejects every directory endpoint with 403, and a source scan asserts no directory endpoint path appears in the connector's request builders.
- [ ] 2.7 Implement the ungranted-site failure per design D15: a site the registration cannot read fails that site's sync with a reason naming the site rather than reporting an empty success.
  verify: a test against the local Graph fake asserts a 403 on site resolution produces a run whose outcome names the site and whose status is not `SUCCEEDED`, and that no item from that site is landed.
- [ ] 2.8 Make the Graph and Entra ID token base addresses settings of the SharePoint connector: `app.connector.sharepoint.graph-base-url`, default the real Microsoft Graph address, and `app.connector.sharepoint.token-base-url`, default the real Microsoft login address (owner answer 86.3 of 2026-10-08), so a national cloud and the e2e stack can point them elsewhere.

  verify: a unit test asserts each default is the real Microsoft Graph and Microsoft login address and that a set value replaces it, and `docker compose config` shows both lines on `ascend-agent` with the code default.
- [ ] 2.9 Make every other value of the Graph client a setting (owner answer 98, design D4): `app.connector.sharepoint.max-file-size` (`APP_CONNECTOR_SHAREPOINT_MAXFILESIZE`, the per-file limit of task 2.3, empty by default, which takes the upload limit `spring.servlet.multipart.max-file-size` of `ingestion-security`, so the two stay aligned, design D4), `app.connector.sharepoint.throttle.max-retries` (`APP_CONNECTOR_SHAREPOINT_THROTTLE_MAXRETRIES`, the retries of one request of task 2.4), `app.connector.sharepoint.throttle.backoff-initial` and `app.connector.sharepoint.throttle.backoff-max` (`APP_CONNECTOR_SHAREPOINT_THROTTLE_BACKOFFINITIAL` and `APP_CONNECTOR_SHAREPOINT_THROTTLE_BACKOFFMAX`, the exponential backoff without `Retry-After`), `app.connector.sharepoint.throttle.run-budget` (`APP_CONNECTOR_SHAREPOINT_THROTTLE_RUNBUDGET`, the total time one run may wait on throttling before it ends `PARTIAL`), and `app.connector.sharepoint.connect-timeout` and `app.connector.sharepoint.read-timeout` (`APP_CONNECTOR_SHAREPOINT_CONNECTTIMEOUT` and `APP_CONNECTOR_SHAREPOINT_READTIMEOUT`, the timeouts of each Graph and token call).
