## Why

The development stack is written and tested on Docker Desktop for Windows, which resolves `host.docker.internal` by itself and accepts Windows host paths. On Docker Engine for Linux the name resolves only when the container declares `extra_hosts: "host.docker.internal:host-gateway"` (or `--add-host=host.docker.internal:host-gateway` on a `docker run`), a Windows path is not a host path, and the Docker socket belongs to the group `docker` instead of `root`. A read-only audit of 2026-10-08 (design, "Audit of 2026-10-08") found that the stack and its documents break on Linux in several places. Owner answer 83 of 2026-10-08: everything in the existing setup that breaks on Linux Docker Engine is fixed in a new, separate OpenSpec change in build group 1, implemented by the agent that implements groups 1 and 2.
